# Bug Tracking Lifecycle

All defects in this project follow a structured bug tracking lifecycle:

1. **Reported:** A bug is created using the GitHub Bug Report issue template.
2. **Triaged:** The bug is evaluated and assigned appropriate severity labels (`severity: high`, `severity: low`).
3. **Assigned:** A team member is assigned to fix the issue.
4. **Fixed in a PR:** A fix is developed on a separate feature branch and merged via Pull Request (referencing `Fixes #n`).
5. **Verified:** The fix is verified against running tests and pipeline builds.
6. **Closed:** The issue is marked as resolved and closed.
